# ArenaPlayTeam Telegram Bot

Go-сервис уведомлений для `@arenaplayteam_bot`. Читает страницу клуба
<https://lhl-77.ru/clubs/686> и находит трансляции в каталоге
<https://vkvideo.ru/@lhl_77/all>. Сообщения отправляет через существующий
зарубежный `telegram-api`, без прямого обращения к Telegram из сервиса.

Проверки выполняются при запуске и в **07:00, 13:00, 19:00 по Москве**.
Первый запуск сообщает обо всех будущих играх. Затем бот сообщает о новых
матчах, переносах даты/времени, изменении арены и появлении трансляций.
Время в сообщениях — московское. Результаты игр и отмены по исчезновению строки
не рассылаются. Видео ищутся до конца дня, следующего за днём матча.

## Настройка и запуск

1. Добавьте бота в группу команды и разрешите отправлять сообщения.
   Для канала нужны права администратора на публикацию.
2. Получите числовой `chat_id`: отправьте сообщение в группу, затем с машины,
   имеющей доступ к Telegram, выполните запрос `getUpdates` для этого бота
   и возьмите `result[].message.chat.id` (для канала — `channel_post.chat.id`).
   Не используйте ID личного чата вместо ID группы. Например:
   ```sh
   read -s TELEGRAM_BOT_TOKEN
   export TELEGRAM_BOT_TOKEN
   python3 - <<'PY'
   import json, os, urllib.request
   url = 'https://api.telegram.org/bot' + os.environ['TELEGRAM_BOT_TOKEN'] + '/getUpdates'
   with urllib.request.urlopen(url, timeout=25) as response:
       for update in json.load(response).get('result', []):
           message = update.get('message') or update.get('channel_post') or {}
           if 'chat' in message:
               print(message['chat']['id'], message['chat'].get('title', ''))
   PY
   unset TELEGRAM_BOT_TOKEN
   ```
   Если ответ пуст, отправьте в группе `/start@arenaplayteam_bot` и повторите.
   Relay поддерживает только отправку; для `getUpdates` нужен прямой доступ.
3. Скопируйте `.env.example` в `.env` и заполните четыре `TELEGRAM_*` настройки.
   `TELEGRAM_RELAY_URL` — полный URL с `/send-message`.
4. Запустите:
   ```sh
   mkdir -p data
   chmod 700 data
   chmod 600 .env
   docker compose up -d --build
   docker compose logs -f backend
   ```

Токен, ключ relay и `.env` не входят в исходники или Docker-образ.
При наличии `$` в значении `.env` заключите его в одинарные кавычки.
Никаких баз данных, внешних Docker-сетей, доменов и открытых портов не требуется.

| Переменная | Значение по умолчанию |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Обязательна |
| `TELEGRAM_CHAT_ID` | Обязательна, ненулевой числовой ID |
| `TELEGRAM_RELAY_URL` | Обязательна |
| `TELEGRAM_RELAY_API_KEY` | Обязательна |
| `CHECK_TIMES` | `07:00,13:00,19:00` |
| `TZ` | `Europe/Moscow` |
| `STATE_FILE` | `/data/state.json` |
| `REQUEST_TIMEOUT` | `25s` на HTTP-запрос |
| `LISTEN_ADDR` | `:8080`, внутренний health endpoint |

`TZ` оставляйте `Europe/Moscow`: время исходного расписания и сообщений московское.
`GET /healthz` возвращает `{"status":"ok"}` после успешной загрузки конфигурации
и состояния. Он проверяет работу процесса; временная недоступность ЛХЛ/VK/relay
фиксируется в логах и не делает процесс нездоровым.

## Состояние и повторы

`./data` на хосте подключается к `/data` контейнера. `state.json` содержит матчи,
последние успешно отправленные данные и время повторной попытки. Запись атомарная,
с синхронизацией на диск. Файловая блокировка запрещает два процесса с одним
состоянием. Один экземпляр обслуживает один чат; смена `TELEGRAM_CHAT_ID` требует
отдельного файла состояния, чтобы случайно не подавить рассылку в новом чате.

После ошибок отправка повторяется через 1, 2, 4, 8, затем каждые 15 минут.
Перед повтором повторно читаются источники; исчезнувшие и устаревшие события
не отправляются. Ошибка VK не мешает сообщать о расписании. Ошибка чтения ЛХЛ
сохраняет прежнее состояние и откладывает отправку. Повреждённый файл состояния
или ошибка записи останавливает сервис; файл не сбрасывается автоматически.

При обрыве связи после фактической доставки возможен дубль: relay не поддерживает
идемпотентность. При отсутствии ID протокола используется ключ турнира/тура/круга/
соперника, затем даты/соперника. Перенос даты без устойчивого ключа может выглядеть
как новая игра. Неоднозначные ссылки VK не отправляются; отдельное сообщение
придёт на следующей проверке, когда ссылка будет найдена однозначно.

Для резервного копирования остановите сервис, скопируйте весь `data`, затем
запустите его снова. Для восстановления остановите сервис и верните каталог
из копии. Удаление состояния приводит к повторной рассылке будущих игр.
Не запускайте старую и новую копии с разными каталогами состояния в одном чате.

## GitHub Actions

Workflow повторяет `dr-notif-backend`: форматирование, vet, race-тесты, сборка,
публикация `linux/amd64` в Docker Hub (`sha-<commit>` и `latest`), деплой через
SCP/SSH, проверка образа и `/healthz`, откат конфигурации и контейнера при ошибке.
Каталог `data` при деплое и откате не удаляется. Тесты выполняются для PR в
`master`; push в `master` и ручной запуск также публикуют и разворачивают образ.
Для проекта используйте отдельный `DEPLOY_HOST_PROJECT_PATH`.

Обязательные GitHub Secrets:

- `DOCKER_USERNAME`, `DOCKER_TOKEN`;
- `DEPLOY_HOST_IP`, `DEPLOY_HOST_USERNAME`, `DEPLOY_HOST_PORT`,
  `DEPLOY_HOST_KEY`, `DEPLOY_HOST_PROJECT_PATH`;
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_RELAY_URL`,
  `TELEGRAM_RELAY_API_KEY`.

Необязательные Secrets: `CHECK_TIMES`, `REQUEST_TIMEOUT`. Часовой пояс деплоя —
`Europe/Moscow`. На сервере должны быть Docker с Compose и права SSH-пользователя
на Docker и каталог проекта. После первого деплоя проверьте логи и права бота
на отправку. Деплой не отправляет тестовые сообщения отдельно от штатного цикла.

## Разработка

Go 1.26 или новее:

```sh
gofmt -w cmd internal
go vet ./...
go test -race ./...
go build ./cmd/server
docker build -t arenaplayteambot:check .
```

Приложение читает переменные окружения, а не файл `.env`; Compose загружает его
самостоятельно. Для локального запуска экспортируйте значения и задайте
`STATE_FILE=./data/state.json`, затем `go run ./cmd/server`.

Тесты не обращаются к живым сайтам и не отправляют сообщения. Они проверяют
парсеры, переносы, перезапуск, повторы и ошибки relay, расписание и защиту файла
состояния. После пересоздания контейнера сохранённые уведомления не повторяются.
