# ArenaPlayTeam Telegram Bot

Go-сервис уведомлений для `@arenaplayteam_bot`. Читает страницу клуба
<https://lhl-77.ru/clubs/686> и находит трансляции в каталоге
<https://vkvideo.ru/@lhl_77/all>. Сообщения отправляет через существующий
зарубежный `telegram-api`, без прямого обращения к Telegram из сервиса.

Проверки выполняются при запуске и в **07:00, 13:00, 19:00 по Москве**.
При подключении группы бот сразу сообщает обо всех будущих играх. Затем сообщает о новых
матчах, переносах даты/времени, изменении арены и появлении трансляций.
Время в сообщениях — московское. Результаты игр и отмены по исчезновению строки
не рассылаются. Видео ищутся до конца дня, следующего за днём матча.
Дополнительно бот читает сохранённые ссылки из `https://arenaplayteam.ru/data/schedule.json`
по точному совпадению даты и соперника: VK может не показывать нужную запись
в текущей выдаче каталога. Ссылка на общий каталог не отправляется как трансляция матча.

## Настройка и запуск

1. Скопируйте `.env.example` в `.env` и заполните `TELEGRAM_BOT_TOKEN`,
   `TELEGRAM_RELAY_URL` и `TELEGRAM_RELAY_API_KEY`.
   `TELEGRAM_RELAY_URL` — полный URL с `/send-message`; relay также должен
   поддерживать `/get-updates`.
2. Запустите:
   ```sh
   mkdir -p data
   chmod 700 data
   chmod 600 .env
   docker compose up -d --build
   docker compose logs -f backend
   ```
3. Добавьте `@arenaplayteam_bot` в группу с правом отправлять сообщения.
   Бот сам сохранит её ID и сразу отправит будущие игры с найденными трансляциями.
   При повторном добавлении он снова объявит будущие игры; при обычном перезапуске
   уже отправленные уведомления не повторяются. До добавления в группы бот
   работает без получателей. При удалении из группы её рассылка отключается.

Токен, ключ relay и `.env` не входят в исходники или Docker-образ.
При наличии `$` в значении `.env` заключите его в одинарные кавычки.
Никаких баз данных, внешних Docker-сетей, доменов и открытых портов не требуется.

| Переменная | Значение по умолчанию |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Обязательна |
| `TELEGRAM_CHAT_ID` | Не задана — необязательный ручной получатель |
| `TELEGRAM_MESSAGE_THREAD_ID` | `0` — общий чат; ID топика для форума |
| `TELEGRAM_ADDITIONAL_TARGETS` | `[]` — дополнительные получатели в JSON |
| `TELEGRAM_AUTO_GROUPS` | `true` — автоматически подключать группы при добавлении бота |
| `TELEGRAM_RELAY_URL` | Обязательна |
| `TELEGRAM_RELAY_API_KEY` | Обязательна |
| `CHECK_TIMES` | `07:00,13:00,19:00` |
| `TZ` | `Europe/Moscow` |
| `STATE_FILE` | `/data/state.json` |
| `REQUEST_TIMEOUT` | `25s` на HTTP-запрос |
| `LISTEN_ADDR` | `:8080`, внутренний health endpoint |

`TZ` оставляйте `Europe/Moscow`: время исходного расписания и сообщений московское.
`GET /healthz` возвращает `{"status":"ok"}` после успешной загрузки конфигурации
и состояния. Он проверяет работу процесса; временная недоступность ЛХЛ/VK/relay
фиксируется в логах и не делает процесс нездоровым.

## Состояние и повторы

`./data` на хосте подключается к `/data` контейнера. `state.json` содержит матчи,
последние успешно отправленные данные и время повторной попытки. Запись атомарная,
с синхронизацией на диск. Файловая блокировка запрещает два процесса с одним
состоянием. Основной получатель использует прежний `STATE_FILE`; смена
`TELEGRAM_CHAT_ID` требует отдельного файла состояния.

### Несколько групп

По умолчанию достаточно добавить бота в новую группу с правом отправки сообщений.
Он получает событие `my_chat_member`, сохраняет ID и начинает рассылку в общий чат
без топика. При удалении бота из группы подписка отключается. Список групп и
позиция чтения событий сохраняются в `state.json.subscriptions.json`; история
игр сохраняется отдельно для каждого получателя. Перезапуск не сбрасывает историю отправок; повторное добавление
снова объявляет будущие игры, чтобы подтвердить подключение.

Для этого зарубежный relay должен поддерживать `POST /get-updates` рядом с
`POST /send-message`. Бот получает только `my_chat_member`, не сообщения группы.
С одним токеном должен работать только один потребитель `getUpdates`, без активного
webhook. Telegram хранит события до 24 часов: добавляйте бота при работающем сервисе;
если событие было пропущено, удалите и снова добавьте его в новую группу.
`TELEGRAM_AUTO_GROUPS=false` отключает автоматическое подключение.

Группы, заданные вручную, не подключаются автоматически ещё раз — это сохраняет
маршрутизацию в текущий топик. Для обычных новых групп ручные настройки не нужны.

Основной чат и его топик остаются в `TELEGRAM_CHAT_ID` и `TELEGRAM_MESSAGE_THREAD_ID`.
Для ручного подключения ещё одной обычной группы задайте в `.env` (ID ниже — пример):

```dotenv
TELEGRAM_ADDITIONAL_TARGETS='[{"chat_id":-1001234567890}]'
```

При деплое через GitHub Actions добавьте Secret `TELEGRAM_ADDITIONAL_TARGETS`
со значением `[{"chat_id":-1001234567890}]` без внешних одинарных кавычек.
Для дополнительных топиков можно указать `message_thread_id` в соответствующем
объекте. Отсутствующее поле или `0` означает общий чат. Добавьте бота в каждую
группу с правом отправки сообщений. После изменения конфигурации пересоздайте
контейнер: `docker compose up -d backend` (или запустите деплой).

У каждого дополнительного получателя своя история в `data`, например
`state.chat--1001234567890.thread-0.json`. Новая группа сразу получает все будущие
игры с найденными ссылками на видео. Текущий чат повторных объявлений не получает.
Ошибки доставки и повторы независимы: недоступная группа не мешает остальным.
Порядок дополнительных получателей можно менять; удаление из списка отключает
отправку, сохраняя историю на случай возвращения. Не удаляйте файлы состояния.

После ошибок отправка повторяется через 1, 2, 4, 8, затем каждые 15 минут.
Перед повтором повторно читаются источники; исчезнувшие и устаревшие события
не отправляются. Ошибка VK не мешает сообщать о расписании. Ошибка чтения ЛХЛ
сохраняет прежнее состояние и откладывает отправку. Повреждённый файл состояния
или ошибка записи останавливает сервис; файл не сбрасывается автоматически.

При обрыве связи после фактической доставки возможен дубль: relay не поддерживает
идемпотентность. При отсутствии ID протокола используется ключ турнира/тура/круга/
соперника, затем даты/соперника. Перенос даты без устойчивого ключа может выглядеть
как новая игра. Неоднозначные ссылки VK не отправляются; отдельное сообщение
придёт на следующей проверке, когда ссылка будет найдена однозначно.

Для резервного копирования остановите сервис, скопируйте весь `data`, затем
запустите его снова. Для восстановления остановите сервис и верните каталог
из копии. Удаление состояния приводит к повторной рассылке будущих игр.
Не запускайте старую и новую копии с разными каталогами состояния в одном чате.

## GitHub Actions

Workflow повторяет `dr-notif-backend`: форматирование, vet, race-тесты, сборка,
публикация `linux/amd64` в Docker Hub (`sha-<commit>` и `latest`), деплой через
SCP/SSH, проверка образа и `/healthz`, откат конфигурации и контейнера при ошибке.
Каталог `data` при деплое и откате не удаляется. Тесты выполняются для PR в
`master`; push в `master` и ручной запуск также публикуют и разворачивают образ.
Для проекта используйте отдельный `DEPLOY_HOST_PROJECT_PATH`.

Обязательные GitHub Secrets:

- `DOCKER_USERNAME`, `DOCKER_TOKEN`;
- `DEPLOY_HOST_IP`, `DEPLOY_HOST_USERNAME`, `DEPLOY_HOST_PORT`,
  `DEPLOY_HOST_KEY`, `DEPLOY_HOST_PROJECT_PATH`;
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_RELAY_URL`,
  `TELEGRAM_RELAY_API_KEY`.

Необязательные Secrets: `CHECK_TIMES`, `REQUEST_TIMEOUT`, `TELEGRAM_CHAT_ID`, `TELEGRAM_MESSAGE_THREAD_ID`,
`TELEGRAM_ADDITIONAL_TARGETS`, `TELEGRAM_AUTO_GROUPS`. Часовой пояс деплоя —
`Europe/Moscow`. На сервере должны быть Docker с Compose и права SSH-пользователя
на Docker и каталог проекта. После первого деплоя проверьте логи и права бота
на отправку. Деплой не отправляет тестовые сообщения отдельно от штатного цикла.

## Разработка

Go 1.26 или новее:

```sh
gofmt -w cmd internal
go vet ./...
go test -race ./...
go build ./cmd/server
docker build -t arenaplayteambot:check .
```

Приложение читает переменные окружения, а не файл `.env`; Compose загружает его
самостоятельно. Для локального запуска экспортируйте значения и задайте
`STATE_FILE=./data/state.json`, затем `go run ./cmd/server`.

Тесты не обращаются к живым сайтам и не отправляют сообщения. Они проверяют
парсеры, переносы, перезапуск, повторы и ошибки relay, расписание и защиту файла
состояния. После пересоздания контейнера сохранённые уведомления не повторяются.

## Необязательные ручные получатели

Для специальных назначений (например, конкретного топика) можно задать
`TELEGRAM_CHAT_ID` и `TELEGRAM_MESSAGE_THREAD_ID`. Эти настройки не требуются
для автоматического подключения обычных групп. Если удаляете ручного получателя,
уберите оба значения из `.env` и GitHub Secrets, чтобы следующий деплой не вернул их.
